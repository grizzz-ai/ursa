# Contributing

Thanks for helping improve this workflow.

Before opening a pull request, open an Issue for a reproducible defect or a concrete improvement. Include
the repository context, the command or workflow step you tried, expected behavior, actual behavior, and
the relevant client and operating-system versions. Never include credentials, private keys, access tokens,
or private repository content.

Keep contributions vendor-neutral, self-contained, and compatible with the repository-local installer.
Changes must not add private Grizzz dependencies, global configuration requirements, or copied third-party
material without clear permission and attribution.

Security vulnerabilities must follow [the security policy](SECURITY.md), not a public Issue or pull request.
